# 数字员工 · 阿抖｜抖音运营专员（MVP v1）

每天交付 **3 个能直接开拍的抖音剧本包**：黄金3秒 Hook 定稿（4进1评分淘汰）+ 精确到秒的分镜表 + 成套 9:16 字卡 PNG（1080×1920，可打包下载）+ 10 项硬规则质检报告（不达标自动打回返工）+ 标题标签 + 剪映组装指引。

抖音是完播逻辑——这位员工的一切产出围绕"前3秒留人+看完"设计，与小红书专员（点击逻辑）是两套完全不同的生产工艺。

---

## 一、部署（Netlify，3 步）

1. 推 GitHub 仓库（或拖 zip 到 Netlify）
2. New site → 选仓库，构建命令 `npm run build`（netlify.toml 已配好）
3. 环境变量（与阿桃同一套 schema，可共用零克云网关）：

| 变量 | 必填 | 说明 |
|---|---|---|
| `LLM_API_BASE` | ✅ | OpenAI 兼容网关，到 `/v1` 为止 |
| `LLM_API_KEY` | ✅ | 网关 Key |
| `LLM_MODEL` | ✅ | 生产模型（写剧本主力） |
| `LLM_MODEL_JUDGE` | 可选 | Hook 评委模型，建议便宜快的；空则同 LLM_MODEL |

本地：`cp .env.example .env.local` → `npm install` → `npm run dev`

## 二、架构对照（代码 ↔ 资产库 docs/抖音运营专员冷启动资产库_v1.md）

| 模块 | 代码 | 资产库章节 |
|---|---|---|
| Hook 24式（结构化） | `lib/hooks.js` | §1 黄金3秒 Hook 库 |
| 剧本5模板（时间块规格） | `lib/scriptTemplates.js` | §2 剧本结构库 |
| 抖音标题16式 | `lib/titleFormulas.js` | §3 标题公式 |
| 分镜表字段规范 | prompts + ScriptCard（TSV导出） | §4 分镜表规范 |
| 选题三板斧 | `lib/prompts.js` topicPrompt | §5 选题三板斧 |
| 质检硬规则机检 | `lib/qc.js`（语速/单镜时长/字幕/违禁词等全代码判定） | §6 十条硬规则 |
| Hook 评分定稿 | `lib/scoring.js` + judgeHooksPrompt | §6 规则1/10 |
| 字卡工厂（6版式×5配色） | `components/frames/` | 一档图文成片字卡层 |
| 发布建议 | 每剧本 tip 字段 | §7 发布与数据策略 |

生产流程：选题（三板斧+制作条件约束）→ Hook 大类分配（三剧本互不相同，规则10由构造保证）→ 3 剧本并行（每本：4 Hook 候选+完整分镜 1 次调用 → 评委打分 4进1 → 首镜台词对齐定稿 Hook）→ 质检环机检 → 硬规则不达标自动打回返工 1 次并复检 → 字卡收集 → 交付。

## 三、产品设计要点

- **质检是真的机检**：语速=台词字数÷时长∈[3.5,5.5]、单镜头≤15s、有词必有幕、时长匹配模板档位——全部代码判定，报告逐项 ✓/✗ 可见，不达标的返工过程写进工作日志
- **Hook 多样性硬保证**：当日 3 个剧本的 Hook 来自 3 个不同大类，由流水线分配而非祈祷模型自觉
- **字卡即半成品**：图文成片型的全部字卡按 9:16 渲染导出，配合"复制完整台词"+ 剪映文本朗读，约 10 分钟出片
- **入职档案含制作条件**：纯字卡/真人口播/可拍剧情，直接约束选题引擎可产类型，不给做不了的活

## 四、v1 边界

- 全自动合成成片（TTS+FFmpeg）需要后端工作器，v2 做；v1 交付"字卡+台词+组装指引"的半自动方案
- 热点/BGM 为半自动投喂（风向层 live 拉取待接热点宝等数据源）
- 单用户 localStorage，无登录；手动开工，定时日更待后端存储

## 五、路线图

v1.1 数据复盘闭环（完播率/互动数据投喂 → 调 Hook 大类与时长档）→ v1.2 TTS+FFmpeg 后端合成（一档/二档全自动成片）→ v1.3 对标拆解周报 → 与阿桃合并进「数字员工花名册」统一入口
